구조 — 요청은 이렇게 흐릅니다

Claude Code는 Anthropic API 서버 대신 내 컴퓨터의 브리지에 말을 겁니다. 브리지가 Microsoft Copilot SDK(구 GitHub Copilot SDK)를 통해 Gemini 4를 호출합니다.

  • 설정은 건드리지 않습니다. claude-gemini 는 실행할 때마다 임시 설정 파일을 만들어 --settings 로 넘깁니다. ~/.claude/settings.json 은 그대로입니다.
  • 모델 이름에 claude- 가 붙는 이유. Claude Code는 게이트웨이가 알려 주는 모델 중 ID에 claude 또는 anthropic 이 들어간 것만 목록에 보여 줍니다(Claude Code 문서). 그래서 Claude Code 안에서는 github-copilot/claude-gemini-4-neon 처럼 보이고, 브리지가 다시 gemini-4-neon 으로 되돌립니다.
  • Claude Code 안의 별칭도 Gemini 4로 고정됩니다. opus→Neon, sonnet→Carbon, haiku→Hydrogen (카탈로그 단가 순서일 뿐 성능 순위가 아닙니다). 그래서 Claude Code가 알아서 보내는 작은 요청도 Gemini 4 밖으로 나가지 않습니다.

  • 입력 한도는 한 번에 넣을 수 있는 입력 토큰 수입니다. 검증에서 런타임이 실제로 부여한 한도가 카탈로그의 이 값과 같음을 확인했습니다(긴 컨텍스트 티어).
  • effort 의 xhigh 는 네 모델 모두 high 로 낮춰 적용됩니다. SDK 런타임이 xhigh 를 거부하기 때문입니다(자세히).

  • Argon은 카탈로그에 2026-12-14 지원 중단 예고가 있습니다. 중단되면 /model 목록에서 자동으로 빠지고, Claude Code 별칭은 Argon을 쓰지 않으므로 나머지 실습은 그대로 동작합니다.

STEP 1설치

의존성을 설치하고, 이 터미널에서 claude-gemini 명령을 바로 쓸 수 있게 합니다.

터미널 — 이 저장소 폴더에서
cd {{repo-name}}
npm ci
export PATH="$PWD/bin:$PATH"   # 이 터미널에서만 유효 · 이후 명령은 이 줄을 전제로 합니다
이렇게 되면 성공
  • npm ci 가 오류 없이 끝납니다 (Copilot SDK {{sdk-version}} 고정).
  • command -v claude-gemini 가 이 저장소의 bin/claude-gemini 경로를 출력합니다.

claude 명령은 바꾸지 않습니다. Gemini 4로 실행할 때만 claude-gemini 를 쓰고, 평소의 claude 는 그대로입니다.

STEP 2점검 — 환경과 모델 확인

두 명령으로 “지금 바로 쓸 수 있는지”와 “Gemini 4 모델 4개가 보이는지”를 확인합니다.

터미널
copilot login        # 처음 한 번만 (브라우저로 인증)
gemini-doctor        # 환경 점검
gemini-models        # 이 계정의 Gemini 4 모델 목록
Signed in as … 가 내가 쓰려는 계정인지 확인하세요

Copilot 로그인은 gh 의 활성 계정과 별개입니다. 다르면 copilot login 으로 다시 로그인하세요. 또 Copilot CLI 세션 안에서 이 명령들을 실행하면 COPILOT_CLI_PATH 가 상속돼 경고가 나옵니다 — 새 터미널을 쓰거나 unset COPILOT_CLI_PATH 하세요.

STEP 3첫 호출 — 한 번 묻고 끝내기

print 모드(-p)로 질문 하나를 보내 Gemini 4가 답하는지 봅니다. 모델은 --ghcp-model 로 고릅니다.

터미널
claude-gemini --ghcp-model gemini-4-hydrogen -p "한국의 수도는 어디인가요? 한 단어로만 답해줘."

4개 모델에 같은 질문 던져 보기

터미널
for m in gemini-4-argon gemini-4-carbon gemini-4-hydrogen gemini-4-neon; do
  echo "== $m"
  claude-gemini --ghcp-model "$m" -p "한국의 수도는 어디인가요? 한 단어로만 답해줘." 2>/dev/null
done
모델을 안 고르면?

기본값은 gemini-4-hydrogen (이 실행에서 가장 빨랐고 카탈로그 단가가 가장 낮음)입니다. 바꾸려면 --ghcp-model 또는 export GHCP_MODEL=gemini-4-neon.

STEP 4대화형으로 시작

연습용 폴더를 만들고 Claude Code를 대화형으로 엽니다. 폴더는 gemini-lab 이 복사해 주고 git 기록까지 시작해 줍니다(나중에 git diff 로 변경을 보기 위해서).

터미널

Claude Code를 처음 쓰는 환경이면 ①~③ 첫 실행 화면이 나옵니다. ④ 폴더 신뢰는 새 폴더를 처음 열 때마다 나옵니다. 이미 Claude Code를 써 왔다면 ④만 보일 수 있습니다.

④에서 그냥 Enter 를 누르면 종료됩니다

폴더 신뢰 화면은 “No, exit” 이 미리 선택돼 있습니다. 반드시 ↓ 를 먼저 누르세요. 이 폴더는 방금 만든 연습용이라 신뢰해도 안전합니다.

모델 목록 열기 → 고르기

/model 을 입력하고 Enter. Gemini 4 모델 4개가 목록에 나옵니다.

Enter 가 아니라 s 를 누르세요

목록 위에는 “Your pick is the default for new sessions.”, 아래에는 “s to use this session only · Enter to save · Esc to cancel” 이라고 나옵니다. Enter 는 이 모델을 새 세션의 기본값으로 ~/.claude/settings.json 에 저장해서, 평소의 claude 가 Anthropic에 없는 모델 이름을 쓰게 만듭니다. 이미 저장했다면 gemini-doctor 가 경고하니 그 파일에서 "model" 줄을 지우세요.

같은 방법으로 Argon, Carbon 으로도 이어서 전환해 보세요.

이름을 “메모리”에서 불러올 수도 있습니다

Claude Code의 자동 메모리가 켜져 있으면 “내 이름은 …” 같은 정보를 메모리에 저장했다가 불러옵니다(화면에 Recalled 1 memory 가 보입니다). 모델이 대화 기록만으로 기억하는지 확인하려면 CLAUDE_CODE_DISABLE_AUTO_MEMORY=1 claude-gemini 로 시작하세요. 이 가이드의 화면과 검증은 모두 이 설정으로 만들었습니다.

STEP 6코딩 실습 — 실패하는 테스트 고치기

Gemini가 테스트를 실행하고, 원인을 찾고, 소스만 고치고, 다시 실행하는 전체 흐름(Bash · Read · Edit 도구)을 봅니다.

먼저 연습 폴더를 새로 만들고 테스트가 실패하는 것을 확인합니다. (숫자를 사전순으로 정렬하는 median 버그가 들어 있습니다.)

터미널
gemini-lab 01 && cd /tmp/lab-01
node --test 2>&1 | grep -E '^(not ok|ok|# (tests|pass|fail))'

grep 은 긴 테스트 출력에서 결과 줄만 걸러 보여 주는 필터입니다. 그냥 node --test 만 실행해도 됩니다.

Neon으로 Claude Code를 엽니다. 이번에는 권한 모드를 직접 지정합니다: 파일 수정은 자동 승인하고, node --test 실행만 허용합니다. 그리고 아래 프롬프트를 붙여 넣습니다(한국어도 됩니다).

터미널
claude-gemini --ghcp-model gemini-4-neon --permission-mode acceptEdits --allowedTools "Bash(node --test)"
왜 권한 모드를 지정하나요?

Claude Code {{claude-version}} 의 기본 권한 모드는 auto mode 입니다. 이 실습처럼 로컬 브리지(127.0.0.1)를 거치는 세션은 새 요금 방식 대상이 아니라서, 도구를 처음 쓰면 “We're changing auto mode to no longer charge for classifier requests…” 안내창이 뜹니다. Enter 로 계속하면 지금은 그대로 동작하지만, 안내문에 따르면 이후 버전에서는 이런 세션의 확인 대상 동작마다 묻거나 거부합니다. 그래서 이 실습은 acceptEdits(파일 수정은 자동 승인)로 시작해 안내창 없이 진행합니다.

Claude Code 프롬프트
node --test를 실행해서 실패하는 테스트의 원인을 찾고, 테스트 파일은 수정하지 말고 소스 파일만 고쳐서 모든 테스트가 통과하도록 해줘. 마지막에 node --test를 다시 실행해서 결과를 확인하고, 결과는 세 줄 이내로 요약해줘.

/exit 로 나온 뒤, 무엇이 바뀌었는지 직접 확인합니다.

터미널
git --no-pager diff
node --test 2>&1 | grep -E '^(not ok|ok|# (tests|pass|fail))'
더 엄격하게 하고 싶다면

이 저장소의 검증은 print 모드에서 도구를 Read,Edit,Bash 로 제한하고 node --test 만 허용했습니다: --restricted --permission-mode dontAsk --tools "Read,Edit,Bash" --allowedTools "Read,Edit,Bash(node --test)"

추론 강도(effort)

{{effort:rows}}
모델low 요청high 요청xhigh 요청

표의 값은 “요청 → 실제 SDK 세션에 적용된 값”입니다. SDK 런타임({{runtime-version}})은 네 모델 모두 xhigh 를 “지원하지 않는 추론 강도” 오류로 거부하므로, 브리지가 high 로 낮춰 적용합니다. 그래서 Claude Code 설정에 effortLevel: "xhigh" 가 있어도 요청이 실패하지 않습니다. (카탈로그에는 Hydrogen·Neon 의 옛 항목에 xhigh 가 남아 있지만, 이 저장소는 런타임이 검사하는 최상위 목록 low · medium · high 를 기준으로 판단합니다.)

한계와 범위

  • 비공식 구성입니다. Anthropic은 Claude가 아닌 모델을 게이트웨이로 연결하는 구성을, GitHub은 이 조합을 지원하지 않습니다. 개인 실험·연구용으로 쓰세요.
  • Claude Code의 확장 사고(thinking) 블록은 표시되지 않습니다. 대신 추론 강도(effort)가 전달됩니다.
  • temperature·top_p·stop_sequences 같은 샘플링 제어와 cache_control 표시는 적용되지 않습니다.
  • WebSearch 처럼 Anthropic 서버에서 실행되는 기능은 쓸 수 없습니다.
  • 모델을 바꾸면 새 모델이 대화 전체를 다시 읽습니다 (Claude Code 확인창의 경고 그대로).
  • 서브에이전트(Explore 등)는 시작할 때 고른 모델로 실행되는 것을 검증했습니다. 도중에 /model 로 바꾼 뒤의 서브에이전트 동작은 검증하지 않았습니다.
